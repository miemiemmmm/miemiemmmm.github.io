Research

Physics-based simulation produces enormous amounts of data; data-driven methods are hungry for it. Most of my work sits at the seam between the two.

Trajectory formats & metadata Making a trajectory file describe itself.

A trajectory on disk is just coordinates. Which force field produced it, which code version, which thermostat — that context usually lives in a lab notebook, a directory name, or someone's memory, and it is the first thing lost.

I lead the integration of metadata and provenance into the H5MD format in GROMACS, so that context travels inside the file itself and a trajectory stays interpretable long after the run that produced it.

FAIR simulation data Shared standards, so simulations outlive the project that ran them.

A format only helps if the rest of the field reads it. I work with the MDDB consortium and with developers of other MD software — NAMD, VMD, ViaMD — on standards that hold across tools rather than inside one of them.

Alongside that, co-development of the MOLSIM ontology gives the domain a shared vocabulary, and earlier work set out a FAIR-compliant way to manage simulation trajectories (J. Chem. Inf. Model. 2025).

Dynamic feature extraction Featurising an ensemble of trajectories, not a single frozen pose.

Structure-based affinity prediction usually starts from one static pose, which throws away exactly what the simulation was run to capture. Nearl instead turns an ensemble of trajectories into voxel-based descriptors of the binding pocket.

The pocket is decomposed into smaller “molecule blocks”, each featurised on its own, so a feature computed from one trajectory can be reused when the same local configuration turns up in a different structure (Bioinformatics 2025).

3D molecular recognition How well do ML models recognise a molecule that keeps moving?

Benchmarks for 3D object recognition mostly use rigid objects. Molecules are not rigid, and a model that scores well on a fixed conformer may be reading pose rather than identity.

FEater is a molecular fragment dataset built to test that honestly across CNN, GNN, PointNet- and Transformer-style architectures (Patterns 2025).

Drug discovery platform Set up, run, store and analyse a campaign without leaving the browser.

Running a screening campaign normally means stitching together system preparation, a scheduler, storage and half a dozen analysis scripts. ACGui closes that loop in one browser-based platform: set the system up, dispatch it to HPC, keep the trajectories, then play them back and analyse them in place.

The automated system-preparation workflow reaches a success rate above 80%, which is what makes running simulations in batch realistic rather than a per-system chore.
